A Script Painted to a Standard

chs-compliancepolicygenerator generates platform specific hardening scripts, for example shell scripts or Ansible playbooks, from a YAML configuration file, using a Jinja2 template for the chosen compliance standard and platform.

Two conditions stand at the front. The configuration must define a non empty policies list. The template is read from templates/<platform>/<standard>.j2 relative to the working directory, so the caller supplies the template tree for their own standards. No template ships with this project, and this page invents none.

Policies List Must Not Be Empty

A configuration without a non empty policies list fails the run instead of producing an empty script.

Taking the tool up, exactly as the source gives it:

git clone https://github.com/ShadowGuard-AI/chs-compliancepolicygenerator

That single clone line is the whole install passage in the source. A note from the repository files: requirements.txt lists jinja2 at version 3.1.2 or above and PyYAML at version 6.0 or above.

The repository on GitHub

One Example Command

python3 main.py --compliance-standard CIS --config-file config.yaml --output-file hardening.sh --platform linux

CIS is the standard, config.yaml is the configuration, hardening.sh is the script that will be written, and linux is the platform.

An illustration from the comments of main.py, labelled as an illustration and not as a shipped template: a configuration whose policies list holds one policy named Disable unnecessary services, with services atd and cups, and a template at templates/linux/CIS.j2 that loops over config.policies and writes systemctl disable and systemctl stop lines for each service.

Four Required Choices

-hShows a help message and exits.
-c, --compliance-standardGives the compliance standard, for example CIS. Required.
-f, --config-fileGives the path to the YAML configuration file. Required.
-o, --output-fileGives the path to the output script file. Required.
-p, --platformGives the target platform, for example linux or windows. Required.

Each working entry carries a dust rose mark at its left, because in this tool nothing is optional except help.

What Was Actually Run

The parameter list comes from the argument parser in main.py, and main.py passes py_compile.

Install Jinja2 and PyYAML First

A live run was not completed in the documenting wave: the jinja2 package is not installed in that environment and installs were not permitted there, so --help and a generation run both stop at that missing import. Install jinja2 and PyYAML from requirements.txt before running.

Two cautions from the code itself. Configuration values land in the output exactly as written and unsanitised, because the output is a script and the template decides where values go, so the configuration file is trusted input, and a service name carrying shell syntax is carried straight into the generated script. Jinja2's default handling renders a mismatched template key as empty text instead of failing, so the generated script needs reading, not just generating.
